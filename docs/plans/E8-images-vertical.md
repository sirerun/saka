# E8 -- Images Vertical

Acceptance: callers can search image results distinct from general web results.
fidelity: executable

Decision rationale: docs/adr/003-search-verticals.md (mechanism) and its
2026-08-29 addendum (this epic's specifics). Source: SearXNG's `categories=images`
query mode against the same self-hosted SearXNG instance this repo already
integrates for general web search (founder decision, 2026-08-29) -- not a
separate image-search API, consistent with saka's "no API keys" posture.
Reuses E7's `Query.Vertical`/`ProviderConfig.Vertical`/per-vertical-chain
mechanism directly; no new ADR, no `chain.Chain` or registry change.

- [x] T8.1 Extend `types.Result` (types/types.go) with three optional fields: `ThumbnailURL string`, `Width int`, `Height int`, all `json:"...,omitempty"`. Zero value when a provider doesn't set them -- general web providers (duckduckgo, searxng, startpage) need no changes and existing callers ignore the new zero-value fields  Owner: hand-implemented (kazi lane approved but never dispatched -- see deviation note)  Est: 20m  Completed: 2026-08-30  PR: #72  verifies: [UC-022]  deps: [T7.1]  acc: [types.Result has ThumbnailURL string, Width int, and Height int fields with omitempty JSON tags, and go build ./... succeeds with zero other files touched]
- [x] T8.2 Implement an images-specific SearXNG provider in provider/searxng (new file images.go, sharing the package's existing HTTP client and base-URL config): self-registers via init() as types.Register("searxng-images", factory) -- a distinct name from "searxng" per ADR 003's addendum, so a saka.json provider entry unambiguously says what it does. Queries SearXNG with `categories=images` added to the existing `/search` request. Parses the image-result JSON shape into []types.Result: `img_src` -> Result.URL (keeps "URL of the thing found" consistent with general web results), `thumbnail_src` -> Result.ThumbnailURL, `title`/`engine` map the same as the general provider, and `resolution` (a string like "1920x1080") is parsed into Width/Height -- a malformed or absent resolution leaves both at zero rather than failing the whole result.
